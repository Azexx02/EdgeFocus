# PRECHECK 手动云台接管与稳定布局设计

## 问题与证据

- 主机在 PRECHECK 自动搜索期间尚未授予 `manual_lease`，但 APP 已允许点击方向键。命令会等待主机自动搜索持有的锁，随后被拒绝或积压，用户看到的结果是“微调未生效”。
- 自动搜索完成后，主机仍保持 `PRECHECK`，并报告 `manual_lease=true`。在该状态下实机左移于 0.43 秒内返回 `accepted=true`，角度从 359° 变为 358°，证明底层微调链路可用。
- 相机帧到达前使用一行占位文字，帧到达后插入全宽 16:9 图片，导致云台按钮整体下移，ADB 实测坐标变化约 418 px。

## 选择的方案

采用“显式跳过后手动接管”方案：

1. APP 解析主机 `runtime_snapshot.gimbal` 中的 `state`、`manual_lease` 和 `detail`。
2. 自动搜索期间，方向、归中、停止和确认按钮禁用；主机自然结束搜索并上报 `manual_lease=true` 后自动启用。方向键不会隐式打断自动搜索。
3. 只有用户显式点击“跳过自动调整”才发送一次 `precheck_skip_auto_adjust`。随后按同一 `session_id` 每 250 ms 拉取一次权威状态，最长等待 6 秒；观察到 `manual_lease=true` 后启用手动控件。超时、phase/session 变化或 skip 被拒绝时不自动重发。
4. 单例 `PrecheckController` 统一拥有 PRECHECK 控制事务门。事务执行期间的新点击直接丢弃，不排队、不合并，也不产生第二条主机命令，避免连续点击形成命令洪泛。
5. 预览区始终保留固定高度。无图时在同一容器内显示占位提示，有图时原位替换，不改变下方云台按钮位置。
6. 首页与横屏控制面板复用相同的租约语义；两处预检预览都采用稳定尺寸。

## 状态与错误处理

- 主机状态是唯一权威来源。APP 不在本地伪造手动租约。
- 如果显式跳过失败，手动按钮保持禁用，页面显示主机返回的错误。
- 若 APP 内存状态落后，微调事务发送前仍同步拉取权威状态；没有手动租约时拒绝命令，不发送 skip。
- 控制响应超时不重建 GATT，后续状态同步仍可核对主机实际结果。

## PRECHECK 生命周期与断线恢复

- PRECHECK 会话本身不设置固定超时。主机只会因 APP 显式确认、APP 显式退出、required prepare 失败或进程关闭而离开 PRECHECK。
- 云台自动搜索保留约 75 秒硬截止；该截止只结束自动搜索、回参考位并授予 `manual_lease`，不会结束 PRECHECK。
- 仅当持久化设置仍为 EDGEFOCUS 模式时，APP 在协议进入 READY 后读取主机权威状态；主机处于 PRECHECK 时恢复 PRECHECK 页面、预览、云台租约状态和退出入口。LOCAL 模式是手机独立模式，不读取、不接管主机会话。
- PRECHECK 退出采用握手：APP 发送一次 `session_control(end)`，随后最长 10 秒轮询权威状态；只有观察到 IDLE 才清理本地 PRECHECK。断线、拒绝或确认超时时保留 PRECHECK 页面，避免把仍在预检的主机遗留为不可操作状态。

## 验证

- 单元测试覆盖运行时云台字段解析和完整命令顺序：有租约时直接执行；无租约时方向键不得发送 skip 或原命令；显式跳过按 false → skip accepted → 拉取 true 完成接管；skip 拒绝或 6 秒确认超时保持禁用；快速点击只产生一项事务且不排队。
- Android 单元测试、Lint、Debug APK 构建全部通过。
- 实机从全新 PRECHECK 开始，自动搜索期间方向键与确认应禁用；点击“跳过自动调整”后应看到 `precheck_skip_auto_adjust accepted=true`，随后方向键启用并能得到 `gimbal_nudge accepted=true`。另一轮不点击跳过，等待自动搜索自然结束后方向键也应自动启用。
- 连续快速点击不得产生并发 PRECHECK 命令洪泛。
- 相机首帧到达前后导出 UI 层级，云台按钮纵坐标保持不变。
- 最后验证确认开始、停止、APP 重启重连及崩溃缓冲区。
