## 各章节写作重点

### 摘要

摘要不要只写“做了一个专注系统”。建议包含四点：

1. 解决什么问题。
2. 用了什么方案。
3. 实现了哪些功能。
4. 项目优势是什么。

推荐写法：

> 针对传统番茄钟只计时、不感知学习状态，以及普通手机专注 App 缺少桌面行为输入的问题，本文设计并实现了一套面向学习场景的嵌入式智能专注辅助系统 EdgeFocus。系统以嵌入式主机为核心，结合摄像头视觉识别、Android App 手机状态上报、BLE 通信和多通道提醒，实现专注预检、会话管理、行为融合、分级提醒和会话报告。系统采用本地优先设计，降低对云端和手机后台的依赖，适合学生自习、备考和个人专注场景。

### 绪论

绪论重点讲“为什么需要这个项目”。不要一开始就堆技术。可以从学生学习痛点切入：

- 学习时间不等于学习质量。
- 手机干扰越来越常见。
- 普通 App 缺少桌面行为感知。
- 云端视觉存在隐私和部署问题。
- 嵌入式本地设备适合做学习桌面助手。

### 需求分析

需求分析要体现工程思维。建议分别写用户需求、功能需求和非功能需求。

用户需求强调“学生能用”；功能需求强调“系统要做什么”；非功能需求强调“系统要稳定、隐私友好、可扩展”。

### 总体方案

总体方案建议配一张系统结构图。没有正式图片时，可以先用以下文字图：

```text
摄像头        Android App
  |              |
视觉状态      手机状态
  |              |
  +------> 嵌入式主机 <------ 按键/电源状态
             |
      行为融合与提醒策略
             |
屏幕 / 声音 / 手机通知 / 外设 / 会话报告
```

### 硬件设计

硬件章节要突出“嵌入式大赛”属性。即使当前硬件还在适配，也可以说明硬件组成和适配思路：

- 主控板负责运行主程序。
- 摄像头负责输入学习行为。
- 屏幕负责人机交互。
- 声音或外设负责提醒。
- 电源模块支持 HOME/GO 模式。
- 自研版和正点原子版分别适配。

### 软件设计

软件章节要体现分层：

- 板端 C++ 模块化。
- Android Kotlin 分层架构。
- BLE 协议层。
- 存储层。
- 行为策略层。

可以用表格说明每个模块职责，评审更容易理解。

### 关键算法与业务逻辑

这一章不要只写“用了 AI”。应重点解释业务判断：

- 视觉状态不是最终提醒等级。
- 手机状态不是最终提醒等级。
- 行为融合综合多种输入。
- 学习 App 不直接判分心。
- 学习 App 不屏蔽视觉走神。
- 娱乐 App 会提高风险。

这部分是项目区别普通番茄钟和普通摄像头 demo 的核心。

### 测试与结果

测试章节应写具体场景，不要只写“测试通过”。例如：

- 正常专注场景。
- 学习 App + 视觉正常。
- 学习 App + 看向别处。
- 娱乐 App + 视觉正常。
- 主机结束 push 丢失。
- BLE 大包响应。
- Release 包模拟 BLE 禁用。
- 数据库迁移。

每个场景可以写“测试方法、预期结果、实际结果、结论”。

### 创新点

创新点不要泛泛写“使用 AI”。建议写：

- 行为感知型专注管理。
- 主机权威状态。
- 视觉和手机状态融合。
- 本地优先隐私友好。
- 多通道分级提醒。
- HOME/GO 电源模式。
- 双硬件版本适配。

### 应用前景

应用前景可以写：

- 学生自习。
- 家庭学习。
- 自习室和图书馆。
- 线上课程。
- 个人工作专注。

注意不要把它写成强制监管系统。更稳妥的表述是“辅助提醒”和“学习复盘”。

### 附录 C：现场演示流程

可列出：

1. 设备开机，显示启动页。
2. App 扫描连接 EdgeFocus。
3. 进入专注预检。
4. 开始专注。
5. 模拟看向别处触发提醒。
6. 模拟娱乐 App 触发提醒。
7. 切回学习 App，不直接手机提醒。
8. 结束专注，查看报告。
9. 切换充电/断电，展示 HOME/GO 模式。

## 写作注意事项

1. 不要夸大为医疗级疲劳检测。
2. 不要写成百分百准确识别走神。
3. 不要把系统描述成监控学生，而应描述为辅助提醒。
4. 不要把 App 写成核心控制器，EdgeFocus 模式下主机是权威状态。
5. 不要混淆手机使用状态、融合后走神等级和提醒等级。
6. 对尚未完全完善的电源管理、模型精度和硬件适配，可以写“当前已具备基础能力，后续继续优化”。

## 报告书评分导向建议

如果比赛更重视嵌入式工程，重点写：

- 板端主机独立运行。
- 硬件外设接入。
- 电源模式。
- 小屏 UI。
- 双硬件适配。

如果比赛更重视创新应用，重点写：

- 从计时到行为感知。
- 视觉与手机状态融合。
- 学习类 App 语义。
- 学习报告和复盘。

如果比赛更重视软件质量，重点写：

- 模块化架构。
- BLE 协议。
- 数据库迁移。
- Release 禁用测试入口。
- 测试用例。
