# EdgeFocus 技术亮点与创新优势

## 一句话概括

EdgeFocus 是一套“嵌入式主机 + 摄像头视觉 + Android App + BLE 协议 + 多通道提醒”的智能专注辅助系统，核心优势是本地化、多模态、可联调、可复盘、可扩展。

## 1. 从普通番茄钟升级为行为感知系统

普通番茄钟只能回答“学习了多久”，EdgeFocus 尝试回答更关键的问题：“这段时间是否真的保持了学习状态？”

系统不仅记录时间，还会在专注过程中持续关注：

- 用户是否在座位上。
- 摄像头画面是否可用。
- 用户是否长时间看向别处。
- 用户是否出现犯困、趴睡、离开等行为。
- 手机当前是否处于学习、普通使用、娱乐或强干扰状态。
- 当前会话是否已经结束、暂停或进入预检。

这让项目从简单计时工具变成一个有感知、有判断、有反馈的嵌入式系统。

## 2. 主机端权威状态设计

EdgeFocus 的重要设计原则是：嵌入式主机是会话状态和报告的权威来源。

这样做有几个优势：

- 手机断连时，板端仍能继续运行专注会话。
- App 不会因为本地计时误差随意保存 EdgeFocus 会话。
- 专注报告由主机统一生成，避免 App 和板端数据互相冲突。
- 更符合嵌入式大赛对“板端真实工作能力”的要求。

在比赛展示中，这一点可以证明系统不是“手机 App 做主要逻辑，板子只负责显示”，而是主机端真正承担核心控制逻辑。

## 3. 多模态行为融合

项目没有把某一个输入源当成绝对判断依据，而是融合视觉侧和手机侧信息。

### 视觉侧

视觉侧主要反映用户在桌面学习场景中的行为状态，例如：

- FOCUSED：正常专注。
- LOOKING_AWAY：看向其他方向。
- AWAY：离开画面或座位。
- SLEEPY_OR_SLUMPED：犯困、低头或趴睡。
- LOW_CONFIDENCE：画面或识别置信度不足。

### 手机侧

手机侧主要反映专注期间的前台 App 使用状态，例如：

- 学习类 App：作为低风险学习上下文。
- 普通使用：说明用户可能在使用手机，但不一定是强干扰。
- 娱乐、游戏、视频或社交：更可能形成强干扰。

### 融合优势

融合之后可以处理更真实的情况：

- 使用学习 App 时，不因为“手机亮屏”直接提醒。
- 使用学习 App 时，如果视觉侧明显走神，仍然可以提醒。
- 使用娱乐 App 时，即使坐姿正常，也可以提高风险。
- 视觉侧和手机侧同时异常时，提醒等级可以更高。

这比单纯摄像头判断或单纯 App 分类更细致。

## 4. 学习类 App 的语义更符合真实场景

项目对学习类 App 的处理不是简单“白名单放行”，而是把它作为低风险上下文输入。

设计口径是：

- 学习类 App 继续上报给板端。
- 学习类 App 本身不在 App 端提醒。
- 学习类 App 本身不直接触发板端手机提醒。
- 学习类手机使用不增加手机干扰次数。
- 学习类 App 不能屏蔽视觉侧明显走神。

这种设计避免两个极端：

- 不会把所有手机使用都视为分心。
- 也不会因为打开学习软件就忽略真实走神行为。

对于学习场景，这是一个非常关键的业务优势。

## 5. 本地优先与隐私保护

EdgeFocus 面向的是学习桌面、自习室、宿舍等敏感场景。摄像头类产品如果强依赖云端，会天然带来隐私顾虑。

本项目强调：

- 行为识别和会话判断以本地设备为核心。
- 原始画面不作为云端处理的核心依赖。
- App 和主机之间通过本地 BLE 通信完成状态同步。
- 数据主要用于本地报告和复盘。

这使项目更适合在学生和家庭学习环境中落地展示。

## 6. 多通道提醒与分级干预

专注提醒不能只有一种方式。提醒太弱，用户可能忽略；提醒太强，又容易打断学习节奏。

EdgeFocus 支持多通道输出：

- 板端屏幕提示。
- 声音提醒。
- 手机通知。
- BLE 外设提醒。
- 会话报告中的事后复盘。

提醒策略可以根据行为严重程度分级，既能处理轻微偏离，也能处理长时间离开、娱乐使用、犯困等更严重情况。

## 7. 预检机制提升使用可靠性

很多视觉类设备的体验问题不是识别算法本身，而是开始时设备未准备好。例如摄像头角度不对、画面没准备好、用户不在画面内。

EdgeFocus 在专注开始前加入预检阶段，用于确认：

- 摄像头画面是否就绪。
- 用户是否进入检测范围。
- 画面状态是否适合开始专注。
- 主机和 App 是否能同步会话状态。

这能提升比赛演示的稳定性，也更符合真实产品体验。

## 8. HOME/GO 电源模式

项目根据供电状态区分两种工作模式：

- HOME：外部供电或充电状态，使用较完整的工作频率，适合桌面固定学习。
- GO：电池供电状态，降低工作频率以节省电量，适合移动携带和临时使用。

这说明项目不是只考虑软件逻辑，也考虑到了嵌入式设备的功耗和使用场景。

## 9. BLE 协议与大包处理

App 与主机通过 BLE 通信。项目不仅实现了基础命令，还考虑了真实 BLE 场景中的限制：

- 状态查询。
- 会话控制。
- 手机使用状态上报。
- 主机主动 push。
- 会话报告和历史记录同步。
- 大响应和大 push 的分包组包。
- 超大请求的明确错误提示，避免静默失败。

这些细节体现了项目从 demo 走向工程原型时的可靠性意识。

## 10. Android App 工程能力

Android 端不是临时调试工具，而是有完整结构的应用：

- Jetpack Compose UI。
- Room 本地数据库。
- BLE 扫描、连接、命令和推送处理。
- AppMonitorService 监控专注期间手机使用状态。
- ViewModel 管理首页、控制面板、设置和连接状态。
- Debug/Release 隔离，避免正式包暴露测试入口和模拟 BLE。
- 数据库迁移，避免升级时破坏用户数据。

这些内容能体现移动端工程能力，而不仅是简单页面。

## 11. 板端 C++ 模块化架构

板端代码按职责拆分，便于学生团队分工和后续硬件适配：

- `app`：会话控制、状态存储、模块生命周期。
- `behavior`：事件检测、行为融合、风险评分、状态机。
- `camera`：摄像头接入与帧处理。
- `device`：屏幕、声音、手环、云台、电源等硬件抽象。
- `network`：BLE GATT、App 命令服务、协议解析。
- `policy`：提醒策略和输出命令。
- `storage`：SQLite 会话和设置存储。
- `ui`：板端屏幕界面。
- `vision`：视觉推理与结果转换。

这种结构适合比赛答辩时展示“系统怎么组织”，也方便不同成员负责不同模块。

## 12. 双硬件版本适配

项目已经进入分硬件版本部署阶段，板端源码被拆分为：

- 自研版硬件。
- 正点原子硬件。

这体现了项目的可迁移性。评审通常会关注作品是否只能在单一开发环境中运行，双硬件版本适配可以证明系统具有更强工程落地能力。

## 13. 测试与审核准备

项目包含针对协议、行为策略、提醒策略、BLE、数据库迁移和 App 逻辑的测试。虽然比赛项目不一定要求完整 CI，但已有测试能体现团队对质量的重视。

特别值得展示的测试方向：

- 学习类 App 不直接计入手机干扰。
- 视觉走神不被学习类 App 屏蔽。
- Local 模式暂停后停止仍保存会话。
- EdgeFocus 倒计时到 0 后有兜底逻辑。
- Release 包禁用开发者入口和模拟 BLE。
- 数据库升级不清空用户历史。

## 14. 面向比赛的核心卖点

可以在答辩中重点强调：

1. 项目不是单一功能，而是完整软硬件系统。
2. 主机端具有真实会话控制和行为判断能力。
3. 融合视觉与手机状态，业务逻辑贴近学习场景。
4. 本地优先，隐私友好，适合学生学习环境。
5. 支持多通道提醒和会话复盘。
6. 已考虑功耗、断连、硬件适配、数据库迁移和正式包安全性。
7. 适合学生团队分工，技术覆盖面广，展示效果直观。

## 15. 可继续扩展方向

后续可以继续增强：

- 优化视觉模型在不同光照和摄像头角度下的稳定性。
- 引入个性化提醒策略，根据用户反馈调整提醒强度。
- 增加更细的学习报告，例如高效时段、常见干扰来源、连续专注趋势。
- 优化外壳结构和电源管理，提升便携性。
- 完善硬件版本抽象，使自研版和开发板版本共用更多业务逻辑。

## 总结

EdgeFocus 的优势不只是“能识别走神”，而是把嵌入式设备、移动端、视觉 AI、通信协议、提醒策略和学习复盘组合成一个完整系统。对于学生嵌入式大赛来说，它具有较强的技术综合性、现场演示性和实际应用价值。
