# EdgeFocus 答辩展示提纲

## 一、30 秒开场版本

各位评委好，我们的项目叫 EdgeFocus，是一套面向学习场景的嵌入式智能专注辅助系统。它不是普通番茄钟，而是通过嵌入式主机、摄像头视觉识别、Android App 和 BLE 通信，把专注过程中的视觉行为、手机使用状态和会话数据融合起来，实现预检、开始专注、走神提醒、会话报告和复盘分析。项目强调本地优先、隐私友好和软硬件协同，适合作为学生学习场景下的智能桌面设备。

## 二、3 分钟答辩结构

### 1. 项目背景

普通番茄钟只能计时，不能判断学生是否真正专注；手机专注 App 又缺少对坐姿、离开、犯困、看向别处等桌面行为的感知。我们希望做一个嵌入式专注主机，让设备在本地完成行为感知和提醒，而不是只依赖手机或云端。

### 2. 系统组成

EdgeFocus 包含：

- 嵌入式主机。
- 摄像头视觉模块。
- Android App。
- BLE 通信协议。
- 多通道提醒。
- 本地会话报告和历史记录。

主机是会话权威状态来源，App 负责连接、控制、展示和手机状态上报。

### 3. 核心功能

- 专注开始前进行摄像头和用户状态预检。
- 专注过程中识别离开、看向别处、犯困等视觉行为。
- App 上报专注期间手机使用状态。
- 主机融合视觉和手机状态，生成分级提醒。
- 会话结束后生成报告，用于复盘学习质量。

### 4. 创新优势

- 从单纯计时变成行为感知。
- 本地嵌入式主机完成核心判断，隐私更友好。
- 视觉和手机状态融合，避免单一规则误判。
- 学习类 App 不直接算分心，但也不能屏蔽视觉走神。
- 支持多通道提醒和双硬件版本适配。

### 5. 总结

EdgeFocus 是一个完整的软硬件系统，覆盖嵌入式、AI 视觉、BLE、Android、数据库和交互设计。它既有实际学习场景价值，也能体现学生团队的综合工程能力。

## 三、5 分钟答辩结构

### 第 1 分钟：问题与目标

可以这样讲：

> 我们观察到，很多学生使用番茄钟时只是完成了“坐够时间”，但这段时间是否真的有效，传统工具并不知道。手机 App 能限制部分娱乐行为，但不知道用户是否离开、犯困或看向别处。摄像头方案如果完全依赖云端，又存在隐私和网络依赖。因此我们设计 EdgeFocus，希望用本地嵌入式设备做一个更真实的专注辅助系统。

重点表达：

- 不是做普通计时器。
- 不是单纯封锁手机。
- 目标是辅助学习过程，而不是惩罚用户。

### 第 2 分钟：系统架构

可以展示一张结构图：

```text
Android App
  | BLE
嵌入式主机
  | 摄像头 / 屏幕 / 声音 / 外设 / 电源
行为融合与提醒策略
  | 
会话报告与历史记录
```

讲解重点：

- App 负责连接、控制、手机状态输入和报告展示。
- 主机负责会话权威状态、行为判断和提醒。
- 摄像头负责桌面视觉行为输入。
- 多通道输出负责提醒。

### 第 3 分钟：关键业务逻辑

重点讲行为融合：

- 视觉侧识别离开、看向别处、犯困等状态。
- 手机侧识别学习、普通使用、娱乐等状态。
- 学习类 App 不直接提醒，也不增加手机干扰次数。
- 但如果用户使用学习 App 时看向别处或犯困，视觉侧仍然可以触发提醒。
- 娱乐类使用会提高风险，和视觉异常叠加时提醒更明显。

这部分是区别普通 App 和普通摄像头 demo 的关键。

### 第 4 分钟：工程实现

可以介绍：

- 板端 C++ 模块化结构。
- Android Kotlin + Compose + Room。
- BLE GATT JSON 协议。
- 大包分片和异常保护。
- Debug/Release 隔离。
- Room 数据库迁移。
- HOME/GO 电源模式。
- 自研版硬件和正点原子硬件适配。

重点是让评委知道项目有工程完整度。

### 第 5 分钟：演示与总结

推荐现场演示：

1. 开机进入启动画面。
2. App 连接 EdgeFocus 主机。
3. 主机进入专注预检。
4. 预检通过后开始专注。
5. 用户看向别处或离开，主机触发提醒。
6. 手机切换到娱乐类 App，App 上报手机状态，主机提醒。
7. 结束会话，App 查看报告。
8. 展示充电和断电时 HOME/GO 模式变化。

总结句：

> EdgeFocus 的价值在于用嵌入式系统把专注管理从简单倒计时升级为本地行为感知、分级提醒和学习复盘的完整闭环。

## 四、8 分钟详细答辩结构

### 1. 项目背景：1 分钟

- 学习场景中存在手机干扰、离开座位、犯困、注意力漂移等问题。
- 普通专注工具只看时间。
- 单纯手机管控不理解桌面行为。
- 单纯摄像头不理解手机使用上下文。
- 云端视觉方案有隐私顾虑。

### 2. 设计目标：1 分钟

- 本地优先。
- 嵌入式主机具备独立运行能力。
- App 与主机可靠同步。
- 视觉和手机状态共同参与判断。
- 提醒要分级，不能过度打扰。
- 会话结束后可复盘。

### 3. 系统架构：1.5 分钟

讲清楚三层：

- 输入层：摄像头、手机使用状态、按键/触控、电源状态。
- 决策层：会话控制、行为融合、提醒策略、状态存储。
- 输出层：屏幕、声音、手机通知、外设提醒、会话报告。

### 4. 核心算法与业务逻辑：1.5 分钟

重点讲：

- 视觉状态不是直接等于提醒等级。
- 手机状态也不是直接等于提醒等级。
- 系统先形成行为上下文，再进行风险判断，最后由提醒策略输出等级。
- 学习类 App 是低风险上下文，不直接产生手机提醒。
- 视觉明显异常时，学习类 App 不会阻止提醒。
- 娱乐类 App 会提高风险。

### 5. 软件工程实现：1 分钟

- 板端 C++ 模块化。
- Android App 分层架构。
- BLE 协议与状态同步。
- 数据库和报告。
- Debug/Release 隔离。
- 测试覆盖关键逻辑。

### 6. 硬件与部署：1 分钟

- 摄像头、屏幕、声音、电源、外设。
- HOME/GO 电源模式。
- 自研版和正点原子版适配。
- 后续硬件 agent 可以分别优化驱动和引脚配置。

### 7. 展示与展望：1 分钟

- 展示完整流程。
- 展望模型优化、外壳设计、个性化策略、学习统计分析。

## 五、推荐现场演示流程

### 演示 1：正常专注

1. 启动设备，展示启动页。
2. App 扫描并连接 EdgeFocus。
3. 进入预检。
4. 预检通过后开始专注。
5. 保持正常坐姿，说明系统不会频繁打扰。

1. 专注运行中，用户看向其他方向。
2. 板端状态变化。
3. 屏幕或声音提醒。
4. App 端状态同步。

### 演示 3：手机干扰

1. 手机打开娱乐、视频或游戏类 App。
2. AppMonitorService 上报手机状态。
3. 主机提高风险并触发提醒。
4. 说明学习类 App 与娱乐类 App 的处理不同。

### 演示 4：会话报告

1. 结束专注。
2. 展示总时长、有效专注时长、提醒次数、手机干扰次数等。
3. 强调系统能复盘学习质量。

### 演示 5：电源模式

1. 外部供电时展示 HOME 模式。
2. 断开外部电源后展示 GO 模式。
3. 说明 GO 模式降低工作频率以节省电量。

## 六、可能被问到的问题与回答

### Q1：为什么不用普通手机 App 就能解决？

普通手机 App 只能了解手机侧行为，无法知道用户是否离开、犯困或看向别处。EdgeFocus 把嵌入式主机和视觉输入加入进来，能覆盖桌面学习状态，同时主机可以脱离手机保持核心会话流程。

### Q2：摄像头会不会有隐私问题？

项目设计为本地优先，核心判断在本地设备完成，不把原始画面作为云端处理的核心依赖。后续也可以继续加入本地存储限制、画面不落盘和用户可见的隐私开关。

### Q3：学习类 App 为什么不直接放行？

因为学习类 App 只能说明手机使用目的可能是学习，但不能证明用户真的专注。如果用户打开学习 App 同时离开座位或看向别处，视觉侧仍然应该触发提醒。

### Q4：为什么需要主机权威状态？

如果 App 单独决定会话，手机断连、后台限制或计时误差都会导致数据不可靠。主机作为权威状态来源，更符合嵌入式设备的设计目标，也让比赛展示更真实。

### Q5：项目和普通 AI 摄像头有什么区别？

普通 AI 摄像头通常只做视觉识别。EdgeFocus 还包含会话控制、手机状态融合、BLE 协议、App、报告、提醒策略和硬件适配，是一个完整学习辅助系统。

## 七、结尾推荐表达

> EdgeFocus 不是为了替代学生自律，而是用嵌入式系统提供更及时、更温和、更可复盘的专注辅助。它把视觉 AI、移动端协同和硬件提醒结合起来，在本地完成核心判断，适合学生学习场景，也体现了嵌入式大赛所重视的软硬件综合能力。
