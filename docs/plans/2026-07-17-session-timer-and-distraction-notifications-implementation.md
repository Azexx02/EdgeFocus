# 会话计时与分神通知修复实施计划

## 1. 主机读取时计时投影

- 修改 `SessionSnapshotPublisher`，新增显式接收单调时刻的投影读取接口，返回副本并复用现有计时计算语义。
- 保留无参数 `read()` 给内部功能读取非计时状态，避免将系统时钟硬编码进领域对象。
- 修改 APP/HTTP 状态序列化入口，统一传入当前 `steady_clock` 时刻。
- 扩展 `test_session_runtime.cpp`，覆盖无模块更新时递减、暂停冻结、恢复续计。

## 2. APP 单调倒计时策略

- 新增纯 Kotlin 策略函数，以当前/新会话身份、阶段、当前显示值和主机值决定可接受剩余时间。
- `applyBoardSessionState` 与兼容校准路径统一调用该策略。
- 新增单元测试覆盖 +1 秒、+10 秒、回到完整时长、新会话和向下校准。

## 3. 通知调度与投递

- 将三档间隔集中到 `DistractionNotificationPolicy`：1 秒、30 秒、10 秒。
- 节流改用 `SystemClock.elapsedRealtime()`；应用切换重置 deadline。
- 前台分类完成后先决策并投递通知，再异步执行 BLE 与数据库副作用。
- 通知 ID 使用类别内递增的新 ID，发送前取消该类别上一条。
- 恢复未知/后台 10 秒提醒路径，明确前台包分类优先。
- 更新策略测试并增加通知 ID 轮换测试。

## 4. 数据库错误隔离

- 检查本地 session 是否存在；不存在则跳过 app usage 插入并记录诊断。
- 所有记录错误在独立边界捕获，不得退出监控循环。

## 5. 验证与交付

- 运行 APP 单元测试与 Debug APK 构建。
- 运行主机会话测试并交叉编译、部署主机程序。
- 无线 ADB 连接 `192.168.10.59:33941`，覆盖安装 APK。
- 实测正式会话倒计时、云台恢复期间连续性、强干扰通知节奏、返回 APP 后停止提醒。
- 保存关键日志与最终变更摘要。

## 6. 实施结果

- APP 全量单元测试和 Debug APK 构建通过。
- APK 已通过无线 ADB 覆盖安装到 `192.168.10.59:33941`。
- 实机会话倒计时从 `24:49` 连续下降到 `23:52`，期间未被旧主机快照回拨到 `25:00`。
- 抖音被识别为等级 2 后，首次缓冲结束即约每 1.03 秒投递一个不同通知 ID；返回 EdgeFocus 后停止提醒。
- 主机会话快照投影测试通过，Windows Debug 主程序完整编译通过。
- 主机 ARM 交叉编译与现场部署等待可用的 WSL/交叉编译环境；APP 防回拨保护不依赖本次主机部署。
