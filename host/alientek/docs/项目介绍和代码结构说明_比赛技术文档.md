# EdgeFocus 项目介绍与代码结构说明（比赛技术文档版）

更新时间：2026-07-03

## 1. 作品概述

EdgeFocus 是一套面向学习场景的本地化专注辅助系统。作品由手机 App、主机、摄像头、云台副板和 BLE 手环组成。系统以学习会话为中心，通过视觉采集和手机使用状态上报识别走神风险，并通过屏幕、声音、手环震动或手机端提示进行干预。会话结束后，主机生成报告，App 展示历史数据并收集用户反馈。

## 2. 系统组成

```text
手机 App
  - 发起/控制会话
  - 上报 phone_sync
  - 展示状态、报告、历史
  - 在自研底板屏幕/声卡不可用时承担展示和声音提示

主机
  - 会话权威状态源
  - 摄像头采集与视觉分析
  - 行为综合判断
  - 提醒策略与提醒路由
  - 数据存储和报告生成

摄像头 + 云台
  - 摄像头提供学习状态图像输入
  - 云台副板通过串口接受主机指令，支持状态查询和小步手动调整

BLE 手环
  - 接收主机写入的 Alert
  - 通过震动和 OLED 提醒用户
```

## 3. 核心演示闭环

```text
App 发起 start
-> 主机进入预检
-> App 根据主机响应展示摄像头预检；如果响应包含云台字段则展示云台校准内容
-> 主机进入 focusing
-> 摄像头/视觉层采集学习状态
-> App 上报手机使用状态 phone_sync
-> 行为层综合视觉与手机输入
-> 策略层输出提醒等级
-> 主机按用户配置选择提醒渠道
-> 手环震动 / 屏幕闪烁 / 声音提示 / 手机提示
-> App 结束会话
-> 主机写入报告
-> App 查看历史并提交反馈
```

## 4. 技术路线

### 本地优先

主机在本地完成会话、状态、提醒策略和报告生成，不依赖云端。这样可以降低网络依赖，提升演示稳定性，也避免学习状态数据离开本地设备。

### 多源走神采集

系统有两类走神输入：

- 视觉输入：摄像头画面经过视觉层处理，输出是否离开、是否看偏、画面质量是否可用等信息。
- 手机输入：App 通过 `phone_sync` 上报当前手机使用状态，包括学习类、普通使用和娱乐类使用。

两类输入在行为层统一处理。手机状态本身不是提醒等级，提醒等级由策略层结合风险上下文输出。

### 分级提醒与可配置渠道

策略层输出 `LEVEL_1 / LEVEL_2 / LEVEL_3` 或休息建议。提醒渠道由 normal/silent 模式和用户配置决定：

- normal 默认启用屏幕、手环、声音。
- silent 默认启用屏幕、手环，不启用声音。
- 若自研底板屏幕或声卡不可用，主机可把屏幕/声音提醒路由给手机 App。

### 模块化主机架构

主机代码按采集、视觉、行为、策略、设备、网络、存储、UI 分层，模块之间通过线程安全状态仓库和有界队列通信，避免单个硬件失败拖垮核心会话链路。

## 5. 主要代码结构

```text
focus_app/app        会话、状态中心、模块生命周期
focus_app/camera     摄像头采集与预览图生成
focus_app/vision     视觉推理与画面质量判断
focus_app/behavior   行为状态机与风险评分
focus_app/policy     提醒等级和渠道路由
focus_app/device     手环、声音、屏幕、云台
focus_app/network    App BLE API 与演示 HTTP 后台
focus_app/storage    SQLite 存储与报告
focus_app/ui         主机本机小屏 UI
```

## 6. 容错设计

- 手机未连接：主机仍能独立运行会话和视觉链路，只是没有手机使用输入。
- 手环未连接：主机记录写入状态，其他提醒渠道继续工作。
- 声卡不可用：声音提醒跳过或路由到手机，不阻塞主流程。
- 屏幕不可用：可设置 offscreen 模式，App 作为主展示屏。
- 摄像头支架不稳定：视觉层可用图片测试链路独立验证。

## 7. 演示重点

比赛展示建议聚焦：

- App 控制会话。
- 主机真实进入 focusing。
- 摄像头画面进入主机并可预览。
- phone_sync 娱乐类输入触发提醒，但不把娱乐类固定等同 LEVEL_3。
- 提醒路由可走手环、声音、屏幕或手机。
- 会话结束后 App 能看到同一 `session_id` 的报告、历史和反馈。
