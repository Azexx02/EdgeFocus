# EdgeFocus 项目介绍与代码结构说明（代码接手版）

更新时间：2026-07-03

## 1. 项目定位

EdgeFocus 是一个本地运行的学习专注辅助主机程序。主机以“会话”为核心，工作机制接近番茄钟：App 发起学习会话，主机接管计时、摄像头采集、视觉分析、行为判定、提醒策略、提醒执行、会话收口与报告生成。

核心链路：

```text
App start
-> 主机会话 precheck
-> App 按主机响应渲染摄像头预检；响应包含 precheck.gimbal 时展示云台校准内容
-> 摄像头采集
-> 视觉层输出姿态/质量/离开等信号
-> App phone_sync 输出手机使用信号
-> 行为层综合视觉与手机输入
-> 策略层输出 LEVEL_1/2/3 或休息建议
-> 路由到板载屏幕/板载声音/手环/手机
-> 会话结束
-> SQLite 存储报告
-> App 查询历史并提交反馈
```

重要语义：

- `PHONE_IN_USE`、`PHONE_IN_PLAYING`、`PHONE_IN_LEARNING` 是手机使用输入/行为状态，不是固定提醒等级。
- `normal` / `silent` 只筛选提醒渠道，不改变提醒等级。
- `precheck.camera` 是通用预检入口，始终用于画面预览和距离/姿态指引。`precheck.gimbal` 只在主机确认“本次会话云台功能已启用、运行时接入云台模块、且运动控制可用”时返回；没有该对象时，App 只做摄像头 precheck，不展示云台内容，也不把云台离线/不安全暴露给普通用户。
- App 只直连主机，不直连手环。
- 主机是会话、状态、报告、提醒策略的权威数据源。
- 手环当前只接收主机写入的 Alert，不提供 ACK、Notify、电量或状态上报。

## 2. 顶层代码结构

主程序在 `focus_app/`，C++17，模块以 `Module` 生命周期运行：

```text
focus_app/
  main.cpp                      组装模块、解析启动参数
  app/                          模块生命周期、全局状态、会话控制
  camera/                       摄像头帧采集、预览图抽样
  vision/                       视觉推理、mock/图片测试、质量评估
  behavior/                     行为状态机、事件检测、风险评分
  policy/                       提醒策略、模式、提醒渠道路由
  device/                       手环 BLE、屏幕闪烁、声音、云台串口
  network/                      App BLE GATT、JSON API、Demo HTTP
  storage/                      SQLite、报告生成
  ui/                           本机屏幕 UI、触摸、页面
  tests/                        单元/集成测试
  config/                       行为参数
```

## 3. 模块职责

### `app/`

- `AppContext`：持有所有模块，按顺序 `init()`，随后为每个模块起循环线程。
- `SystemStateStore`：线程安全状态中心。App 查询、UI 展示、策略层、设备层都从这里读写快照。
- `SessionController`：会话 start / pause / resume / end / skip_precheck，结束时生成并持久化报告。
- `SessionPhase`：把 session 状态推导为 `idle / precheck / focusing / paused`。

### `camera/` 与 `vision/`

- `CameraPipeline`：真实摄像头采集，并周期性写入 `CameraPreviewImage`，供 App 预览。
- `VisionEngine`：从摄像头帧或 mock/picture 测试输入产生 `VisionResult`。
- `FrameQuality`：输出预检提示，如距离/姿态是否需要调整。

当前摄像头和视觉层允许断开测试。没有合适支架时，可先验证真实画面进入主机，再用 `picture_test` 图片验证视觉后链路。

### `behavior/`

- `EventDetector`：把视觉结果与 phone signal 变成行为事件。
- `FocusStateMachine`：输出 `FOCUSED / LOOKING_AWAY / AWAY / PHONE_IN_USE / PHONE_IN_PLAYING / PHONE_IN_LEARNING` 等状态。
- `RiskScorer`：输出上下文风险分。手机输入按 `distraction_level` 贡献风险，不把某个手机状态硬编码为固定等级。
- `BehaviorEngine`：消费视觉队列与 `phone_sync` 缓冲，更新 `SystemStateStore.behavior_context` 和 session 统计。

### `policy/`

- `ReminderPolicy`：只在 `FOCUSING` 阶段处理提醒；根据行为状态、风险分、手机输入强度、冷却时间输出 `InterventionCommand`。
- `NotificationRouter`：根据 normal/silent 模式和用户配置，把提醒拆成 `SCREEN / BAND / SOUND` 动作。
- `screen_output_route` / `sound_output_route`：分别控制板载屏幕/板载声卡是否由 App 接管。`screen_output_route=phone` 表示 App 承担主展示、预检画面、报告展示和屏幕类提醒；`sound_output_route=phone` 表示 App 承担提示音播放。为 `phone` 时，主机跳过对应板载硬件路径，避免屏幕或声卡驱动异常影响主流程。

### `device/`

- `DeviceManager`：消费提醒动作队列，调用手环、声音、屏幕闪烁。
- `BleBandController`：主机作为 BLE Central，连接手环并写 `0x2A56` Alert。
- `SoundController`：声音提醒，播放异步执行；声卡可用性探测不再调用 `aplay -l`，避免设备树/ALSA 异常拖住主线程。
- `ScreenController`：屏幕闪烁入口；设备层记录动作，板载可见提示由 UI 的提醒横幅/弹窗承接，手机路由时由 App 承接。
- `GimbalController` / `GimbalMonitor`：串口控制云台副板，轮询状态并执行小步手动控制。`gimbal_enabled=false` 或 `EDGEFOCUS_DISABLE_GIMBAL=1` 时，云台链路整体禁用。

### `network/`

- `BleGattServer`：主机作为 BLE Peripheral，暴露 App BLE GATT 服务。
- `AppCommandService`：处理 App 写入的 JSON 命令；`session_control start` / `get_current_state` 的 `precheck` 字段决定 App 当前预检 UI，`phone_sync` 响应只表示输入已收下，不代表最终行为判定。
- `PhoneSyncParser`：App BLE 与 Demo HTTP 共用的 phone_sync 解析。
- `DemoHttpServer`：仅演示构建启用，主机浏览器后台，不放进 App。

### `storage/`

- `SQLiteStore`：所有 SQLite handle 访问都经过 store 级互斥保护；模块线程、App 命令线程和 shutdown drain 不应直接绕过该类访问数据库。
- 电池字段当前未接入真实检测；App API 用 `battery_available=false` 和 null 电量表示未知。

### `ui/`

- `UIManager` 与页面：本机小屏控制与展示。
- `FrameBuffer`：优先 SPI LCD，其次 `/dev/fb0`，最后 offscreen。新增 `EDGEFOCUS_DISABLE_LCD=1` 或 `EDGEFOCUS_LCD_BACKEND=offscreen/fbdev` 可跳过 SPI LCD 初始化，适配屏幕驱动失败的自研底板。

## 4. 关键数据流

```text
CameraPipeline -> BoundedQueue<CameraFrame>
VisionEngine -> BoundedQueue<VisionResult>
BehaviorEngine -> SystemStateStore.focus_state / behavior_context / session counters
ReminderPolicy -> DeviceManager.issueAction(...) + push_alert
DeviceManager -> BleBandController / ScreenController / SoundController
SessionController -> SQLiteStore / ReportGenerator
BleGattServer -> AppCommandService -> SystemStateStore / SessionController / GimbalMonitor
```

队列是非阻塞边界。提醒策略线程不会等待屏幕或声卡执行；策略只入队，设备线程执行。

## 5. 硬件失败策略

- 没有手机连接时，主机仍能运行视觉链路；没有 `phone_sync` 不阻塞会话。
- 手环未连接时，Alert 会记录诊断状态，不阻塞主流程。
- 声卡不可用时，声音提醒跳过，不阻塞主线程。
- 屏幕不可用时，可配置 `EDGEFOCUS_DISABLE_LCD=1` 或 `EDGEFOCUS_LCD_BACKEND=offscreen`，让 UI 使用 offscreen，App 作为主要展示屏。
- 声卡不可用时，可配置 `EDGEFOCUS_DISABLE_SOUND=1`。
- 屏幕整体由 App 承接时，设置 `screen_output_route=phone`。
- 声音整体由 App 承接时，设置 `sound_output_route=phone`。
- 云台调试不稳定时，配置 `EDGEFOCUS_DISABLE_GIMBAL=1`，主机保留会话、视觉、行为、提醒、报告闭环。
- 自研底板若屏幕/声卡驱动不稳定，建议设置：

```bash
EDGEFOCUS_DISABLE_LCD=1
EDGEFOCUS_DISABLE_SOUND=1
```

并把 App preference 中：

```json
{
  "screen_output_route": "phone",
  "sound_output_route": "phone"
}
```

## 6. 运行/部署配置备忘（代码接手用，不写入比赛提交技术文档）

这些配置用于开发机、自研底板或录制环境切换，属于工程入口，不是普通用户设置。

### 硬件旁路

- `EDGEFOCUS_DISABLE_LCD=1`
  - 启动时强制旁路板载 LCD，UI 使用 offscreen，不初始化 SPI LCD。
  - 同时会把主机偏好里的 `screen_output_route` 视为 `phone`。
- `EDGEFOCUS_LCD_BACKEND=offscreen`
  - 只让 UI 使用内存 framebuffer，不碰真实屏幕。
  - 适合屏幕驱动不稳定但仍要跑主流程的系统。
- `screen_output_route=phone`
  - 偏好配置，表示 App 完整承担主展示、预检画面、报告展示和屏幕类提醒。
  - 当前代码会让 `UIManager` 直接使用 offscreen，并跳过触摸初始化。
- `EDGEFOCUS_DISABLE_SOUND=1`
  - 启动时旁路板载声卡，避免 ALSA/声卡驱动异常影响主流程。
  - 同时会把主机偏好里的 `sound_output_route` 视为 `phone`。
- `sound_output_route=phone`
  - 偏好配置，表示 App 承担提示音播放，主机提醒通过 `push_alert.phone_actions` 下发 `SOUND`。
- `EDGEFOCUS_DISABLE_GIMBAL=1`
  - 启动时关闭云台主流程能力；`precheck.gimbal` 不返回，App 只展示摄像头预检。

### 视觉/演示

- `EDGEFOCUS_VISION_MODE=mock`
  - 使用 mock 视觉源，适合无支架或无摄像头时跑主流程。
- `EDGEFOCUS_DEPLOY_VISION_MODE`
  - 部署脚本传给板端的视觉模式，默认 `mock`。
- `EDGEFOCUS_DEPLOY_DEMO_HTTP=ON`
  - 远程构建时启用 Demo HTTP 代码，默认 OFF。
- `EDGEFOCUS_DEPLOY_DEMO_HTTP_PORT=<port>`
  - 部署后启动 Demo HTTP 端口；只用于录视频，不进入 App。

### 提醒偏好默认值

- `normal_channels_mask=7`：normal 默认 `SCREEN + BAND + SOUND`。
- `silent_channels_mask=3`：silent 默认 `SCREEN + BAND`，不含 SOUND。
- `default_focus_duration_min=25`：App 未传本次时长时使用。
- `sound_volume=0.7`：声音提醒默认音量。

推荐自研底板屏幕/声卡未稳定时：

```bash
EDGEFOCUS_DISABLE_LCD=1
EDGEFOCUS_DISABLE_SOUND=1
```

并在主机偏好中保存：

```json
{
  "screen_output_route": "phone",
  "sound_output_route": "phone"
}
```

## 7. 构建与验证

本地 Windows 已能用 VS BuildTools/NMake 编译部分测试：

```powershell
cmd /c "call ""C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvarsall.bat"" x64 && cmake --build focus_app\build_local_nmake --target test_device_manager && focus_app\build_local_nmake\tests\test_device_manager.exe"
```

远端 ARM 构建：

```powershell
python deploy\remote_build.py
```

演示 HTTP 构建：

```powershell
$env:EDGEFOCUS_DEPLOY_DEMO_HTTP='ON'
python deploy\remote_build.py
Remove-Item Env:EDGEFOCUS_DEPLOY_DEMO_HTTP
```

注意：远端交叉编译机生成的是 ARM aarch64 可执行文件，不能直接在 x86 编译机用 `ctest` 运行。
## Demo HTTP cleanup boundary

- `DemoHttpServer.*` is video-only and must not be wired into the App surface.
- Remote access for recording uses the board host IP plus the configured `--demo-http-port`; the demo server must stay reachable beyond `127.0.0.1`.
- Default remains OFF. The demo server only comes up when `EDGEFOCUS_WITH_DEMO_HTTP=ON` and a positive `--demo-http-port` are both provided.
- Source cleanup before submission is centered on `EDGEFOCUS_WITH_DEMO_HTTP`: remove `DemoHttpServer.*`, `tests/test_demo_http.cpp`, the guarded test target, the guarded entry in `main.cpp`, the CMake/deploy switch, and the guarded `DemoOverride` path in `SystemStateStore` / `BehaviorEngine`.
