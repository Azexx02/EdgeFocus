EdgeFocus 逻辑概览与功能拓展指南
本文档重点阐述了 EdgeFocus 开发板部分的核心判断逻辑（如专注状态推断、提醒策略）以及未来扩展新硬件或新逻辑的接入方式。

一、 核心判断逻辑 (Judgment Logic)
EdgeFocus 的判断逻辑采用了 “视觉特征 -> 时序事件检测 -> 状态机防抖 -> 策略分发” 的分层流水线架构。

1. 事件检测规则 (EventDetector)
视觉引擎每帧产生的 VisionResult 会被放入一个 30 秒的滑动窗口 (SlidingWindow) 中进行时序分析。 优先级从高到低依次检测：

画面质量过低 (Low Confidence)

逻辑：在滑动窗口中，如果 isLowConfidence() 的帧数比例超过了阈值（low_confidence_ratio）。
目的：防止摄像头被遮挡或光线极差时产生误判。
离座 (Away)

逻辑：连续出现 isAway() 的帧的时间长度 ≥ away_confirm_ms（默认 5 秒）。
目的：过滤掉偶尔低头捡东西导致的瞬间人脸消失。
疲劳/趴桌 (Sleepy or Slumped)

逻辑：连续检测到头部状态为 DOWN（低头）的时间 ≥ slumped_confirm_ms（默认 10 秒）。或者连续检测到闭眼/体态懒散时间 ≥ sleepy_confirm_ms。
目的：捕捉长时间的疲劳状态。
玩手机（Phone In Use / Phone In Learning / Phone In Playing）

逻辑：从 VisionResult::phone 字段读取手机检测结果（视觉检测），或从手机端 BLE 上报的 phone_sync 信号触发。输入在最近 5 秒内活跃时，作为 PHONE_IN_USE / PHONE_IN_LEARNING / PHONE_IN_PLAYING 语义参与行为融合，不直接映射固定提醒等级。
2. 状态机与防抖 (FocusStateMachine)
检测出的 FocusEvent 会被映射为候选状态（Candidate State）。

状态优先级：LOW_CONFIDENCE > AWAY > PHONE_IN_PLAYING > PHONE_IN_USE > PHONE_IN_LEARNING > SLEEPY_OR_SLUMPED > LOOKING_AWAY > FOCUSED。
防抖策略 (Hysteresis)：
进入异常状态（打断）：立即进入（耗时 0 ms），保证提醒的及时性。
恢复专注状态：候选状态必须连续维持在 FOCUSED ≥ state_hysteresis_ms（通常 3 秒）后，系统才会真正切换回 FOCUSED 状态。避免状态在边缘疯狂横跳。
3. 提醒策略分发 (ReminderPolicy)
当前状态改变后，由策略层决定如何下发指令。

映射关系：
LOOKING_AWAY → LEVEL_1（轻度提醒）
PHONE_IN_USE / PHONE_IN_LEARNING / PHONE_IN_PLAYING → 由行为/策略综合风险上下文决策 LEVEL_1~LEVEL_3
SLEEPY_OR_SLUMPED → REST_SUGGESTION（休息建议）
AWAY / LOW_CONFIDENCE → 不提醒。
冷却机制 (Cooldown)：
默认发出一次提醒后，会有 base_cooling_ms_ (5 秒) 的冷却期。
在 HOME (严格) 模式下，冷却时间减半（频率更高）。
用户若手动消警 (onUserAck)，冷却时间临时翻 3 倍，避免短时间内过度打扰。
静音降级：
如果在 SILENT (静音) 模式下，命令仍按行为/策略产出，不会降低严重级别；仅过滤不可用通道（例如无声/无屏等），由主模式约束输出路径。
二、 已实现的外部接入与交互方式 (Implemented Integrations)
项目在开发板环境下，已经与底层硬件和外部脚本实现了多种维度的交互与接入。

1. 外部干预外设：蓝牙手环 (BleBandController)
触发场景：当系统决定下发强提醒（如 LEVEL_3）时。
接入方式：通过 C++ system() 调用底层 Shell 脚本 (bash /root/scripts/send_ble_signal.sh &)。该脚本负责通过蓝牙协议向配对的震动手环发送唤醒或震动指令。
2. 外部干预外设：屏幕闪烁控制 (ScreenController)
触发场景：中度或重度提醒（如 LEVEL_2，LEVEL_3）。
接入方式：通过 GPIO（PD8 背光）或 FrameBuffer 交替刷帧实现物理闪烁。
3. 外部输入：触摸屏交互 (UIManager)
触发场景：用户操作 UI 界面（如切换页面、点击消警）。
接入方式：在 Linux 系统下，UIManager 初始化时会遍历并打开 /dev/input/event* 设备节点，监听底层的触摸屏驱动事件（拦截 EV_ABS 绝对坐标以及 EV_KEY 的 BTN_TOUCH 触摸按下/抬起状态），将其映射为内部坐标后传递给各个 Page 进行处理。
4. 外部信号注入：手机使用特征检测 (PhoneUsageSignal)
触发场景：检测到学习期间在使用手机。
接入方式：两种路径：(1) 手机端通过 BLE 上报 `phone_sync` 命令，BleGattServer 接收后注入 EventDetector；(2) VisionResult::phone 字段由视觉模型直接检测。任一路径触发后，输入语义映射为 PHONE_IN_USE / PHONE_IN_LEARNING / PHONE_IN_PLAYING，再由 FocusStateMachine 决定状态。
5. 底层 AI 算力加速接入 (PoseModelAdapter)
触发场景：视觉引擎 VisionEngine 进行头部姿态推断时。
接入方式：系统支持通过 CMake 宏 EDGEFOCUS_WITH_STAI_MPU 开启对 STM32MP257 硬件 NPU 的支持。此时会链接 stai_mpu_network.h 及对应的底库，把运算卸载到专用加速器上执行，极大地提升了帧率并降低了 CPU 功耗。
